## Why

AIBoarding has a working cross-agent onboarding lifecycle and a useful core story, but its public surfaces do not yet present one current, recognizable, evidence-backed brand: the README still advertises v0.5.0 while v0.6.0 is released, the existing icon is not carried through a complete asset system, and visitors lack a demonstration-first path from problem to trusted installation. Aligning product truth, positioning, visuals, marketplace copy, and community trust now will make the repository easier to recognize, try, and evaluate without overstating support or proof.

## What Changes

- Audit public claims against executable behavior, manifests, releases, and retained evidence; correct stale version, support, verification, and installation wording before amplifying it.
- Center the brand on AIBoarding's existing product truth: maintainers give coding agents current repository onboarding instead of repeated rediscovery and onboarding drift.
- Reuse and refine the existing document/route/check mark into a coherent, original asset family with theme-aware README treatment, small-size icon output, a real product demonstration, accessible alt text, and a 1280x640 social preview.
- Reorder the README as a visitor journey: recognize the problem, see representative behavior, try the primary supported path, inspect proof and limitations, understand safety and compatibility, then explore architecture and contribution paths.
- Align Claude marketplace, Codex plugin, repository metadata, badges, and calls to action with the same concise positioning and only currently supported capabilities.
- Complete the minimum public trust surface with focused contribution, conduct, issue, pull-request, security, and support navigation; defer governance and standalone support policy until project participation requires them.
- Add deterministic checks for referenced assets, portable SVG/PNG structure and dimensions, manifest asset paths, README links, and cross-surface claim/version consistency.
- Document the administrator-only GitHub metadata steps, including uploading the committed social preview, without treating those external actions as completed by repository changes.

## Capabilities

### New Capabilities

- `repository-branding`: Defines the truthful positioning, visual identity, README journey, distribution copy, accessible assets, public trust surface, and validation required for a coherent AIBoarding brand.

### Modified Capabilities

None.

## Impact

Primary impact is limited to public documentation and distribution surfaces: `README.md`, `assets/`, Claude/Codex manifests, focused community-health files under the repository root and `.github/`, and deterministic documentation/plugin checks under `tests/`. No runtime behavior, onboarding lifecycle semantics, package dependency, compatibility guarantee, or release publication is changed. GitHub description, topics, and social-preview activation remain explicit maintainer actions because they live outside the repository.
